# Diff for migration 0057

Migration file: `cms-migrations.ts` — `migration_0057_provider_system_routing`

## Table Changes

### `provider_instances` — system-only use metadata

```diff
+ display_name            TEXT
+ system_use_enabled      BOOLEAN NOT NULL DEFAULT FALSE
+ system_use_enabled_by   BIGINT REFERENCES users(user_id)
+ system_use_enabled_at   TIMESTAMPTZ
```

A personal provider remains private to its owner. `system_use_enabled` permits
only global system sessions to consume it and does not widen the ordinary user
namespace.

### `provider_cluster_settings` — independent system default

```diff
+ system_default_provider    TEXT
+ system_default_model       TEXT
+ system_default_reasoning   TEXT
+ system_default_context     TEXT
+ system_default_updated_by  BIGINT
+ system_default_updated_at  TIMESTAMPTZ
```

The audit actor is deliberately not a foreign key: deleting or truncating a user
must not cascade-delete the singleton cluster settings row.

### `system_agent_model_overrides` — new table

```sql
CREATE TABLE system_agent_model_overrides (
    agent_id          TEXT PRIMARY KEY,
    provider_name     TEXT NOT NULL REFERENCES provider_instances(name),
    model_qualified   TEXT NOT NULL,
    reasoning_effort  TEXT,
    context_tier      TEXT,
    updated_by        BIGINT NOT NULL REFERENCES users(user_id),
    updated_at        TIMESTAMPTZ NOT NULL DEFAULT now()
);
```

## New Indexes

```sql
CREATE INDEX system_agent_model_overrides_provider
    ON system_agent_model_overrides(provider_name);
```

## Function Changes

### New functions

```diff
+ cms_provider_assert_system_eligible(name, actor)
+ cms_provider_set_system_use(name, enabled, actor, is_admin)
+ cms_provider_set_system_default(provider, model, reasoning, context, actor, is_admin)
+ cms_provider_set_system_agent_model(agent_id, provider, model, reasoning, context, actor, is_admin)
+ cms_provider_clear_system_agent_model(agent_id, actor, is_admin)
+ cms_provider_list_system_agent_models()
```

These functions enforce that shared providers are system-eligible and a personal
provider is eligible only when the calling admin both owns it and explicitly
enabled system use.

### `cms_provider_delete` — body modified (baseline: 0050)

```diff
+ IF provider is referenced by a cluster/user/system default or system-agent
+ override THEN raise PROVIDER_IN_USE
- silently clear cluster and user defaults after delete
```

Configured routing must be cleared deliberately before provider deletion.
Historical usage rows and active-session behavior remain unchanged.

### `cms_provider_set_cluster_default` — body modified (baseline: 0050)

```diff
+ accept `(NULL, NULL)` to clear the configured ordinary-session default
+ require both provider and model when setting
```

The shared-provider-only rule remains unchanged.

### `cms_provider_list` — return shape widened (baseline: 0051)

```diff
+ display_name TEXT
+ system_use_enabled BOOLEAN
+ system_eligible BOOLEAN
+ is_system_default BOOLEAN
```

System eligibility is viewer-scoped: shared providers qualify; a personal
provider qualifies only for its owner when system use is enabled.

### `cms_provider_get_defaults` — return shape widened (baseline: 0050)

```diff
+ system_provider TEXT
+ system_model TEXT
+ system_reasoning TEXT
+ system_context TEXT
+ system_updated_by BIGINT
+ system_updated_at TIMESTAMPTZ
```

The existing cluster and user ordinary-session fields are unchanged.
