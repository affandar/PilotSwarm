# Diff for migration 0063

Migration file: `cms-migrations.ts` — `migration_0063_agent_package_editors`

Two changes that ship together: **package editors** (write grants on a
shared agent package) and **the picker fix** (every signed-in user is
findable in share dialogs).

## Table Changes

### `agent_package_editors` — new

```sql
agent_package_editors (
  package_id TEXT        NOT NULL REFERENCES agent_packages(package_id) ON DELETE CASCADE,
  user_id    BIGINT      NOT NULL REFERENCES users(user_id),
  granted_by BIGINT      REFERENCES users(user_id),
  granted_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  PRIMARY KEY (package_id, user_id)
)
INDEX agent_package_editors_user_idx (user_id)
```

Mirrors `session_shares`: keyed on `users.user_id`, one row per grant, no
access level (there is only "editor"). Rows exist only on shared package
copies (the grant proc refuses others). Deleting the package cascades.

## Function Changes

### `cms_agent_package_is_editor` — new

`(package_id, provider, subject) → boolean`. The one predicate every other
function uses.

### `cms_agent_package_authz` — signature changed (baseline: 0043)

```diff
  cms_agent_package_authz(p_name, p_actor_provider, p_actor_subject, p_is_admin,
-                         p_sel_scope, p_sel_owner_provider, p_sel_owner_subject)
+                         p_sel_scope, p_sel_owner_provider, p_sel_owner_subject,
+                         p_allow_editor BOOLEAN DEFAULT FALSE)
```

The seven-argument overload is dropped first (leaving it would make every
seven-argument call ambiguous). With `p_allow_editor = TRUE`: an editor of
the resolved row passes; a caller with no own copy and no selector falls
through to the shared copy (the only row a grant can exist on). With the
default `FALSE` the rule is unchanged: owner or admin.

### `cms_set_agent_package_enabled`, `cms_pin_agent_package_version` — body modified (baseline: 0043)

Call authz with `p_allow_editor = TRUE`. Same signatures.

### `cms_set_agent_package_scope` — body modified (baseline: 0043)

Owner-or-admin as before. The demote branch (shared → user) now runs
`DELETE FROM agent_package_editors WHERE package_id = …` before the scope
update, in the same statement. A demotion that fails its collision check
leaves the grants intact.

### `cms_publish_agent_package` — body modified (baseline: 0043)

The existing-package gate becomes admin OR owner OR editor. The row keeps
its owner; an editor's publish never reassigns the package. Error text:
`AGENT_PACKAGE_FORBIDDEN: only the package creator, an editor, or an admin
can publish new versions of "…"`.

### `cms_agent_package_require_shared` — new

`(name, actor_provider, actor_subject, is_admin)`. Raises
`AGENT_PACKAGE_NOT_SHARED` when the name has no shared copy but the actor
can see a copy (their own, or any as admin), and `AGENT_PACKAGE_NOT_FOUND`
when they can see none. Without it, resolving with the selector pinned to
`shared` told the owner of a private copy that their package "does not
exist".

### `cms_grant_agent_package_editor` — new

`(name, provider, subject, actor_provider, actor_subject, is_admin)`.
`require_shared`, then owner-or-admin authz on the shared copy. Errors:
`AGENT_PACKAGE_NOT_SHARED`, `AGENT_PACKAGE_NOT_FOUND`,
`AGENT_PACKAGE_EDITOR_IS_OWNER`. Creates the grantee `users` row
create-only (0033's rule), then `INSERT … ON CONFLICT DO NOTHING`. No
registry epoch bump.

### `cms_revoke_agent_package_editor` — new

Same gates; idempotent delete.

### `cms_list_agent_package_editors` — new

`(name) → (provider, subject, email, display_name, granted_at,
granted_by_display)` for the shared copy. Raises `AGENT_PACKAGE_NOT_FOUND`
when no shared copy exists, so "no editors" and "no such package" stay
distinguishable. No viewer argument: a shared package is visible to
everyone, and so is its editor list.

### `cms_register_user` — body modified (baseline: 0032)

The email-keyed ghost adoption loop now also re-points
`agent_package_editors` rows (`user_id` where the real user holds no grant
on that package, `granted_by` always) before deleting the placeholder. Before
this, a placeholder that had been granted an editor row blocked the
`DELETE FROM users` with an FK violation and the whole first-sign-in
registration rolled back.

### `cms_list_agent_packages`, `cms_get_agent_package` — return type changed (baseline: 0043)

Dropped and recreated with one new trailing column:

```diff
+ can_edit BOOLEAN   -- admin OR owner OR editor, for the viewer
```

### `cms_list_users` — body modified (baseline: 0031)

```diff
-      AND u.display_name IS NOT NULL
+      AND NOT (u.provider = 'none')
+      AND (u.display_name IS NOT NULL OR u.email IS NOT NULL)
```

The no-auth provider's anonymous principal (`none`/…) is excluded like the
`system` and `local` synthetic rows.

Why: 0042 registers every user at login, but an Entra access token without
a `name` claim writes a row with `email` set and `display_name` NULL, and
that row was hidden from every share dialog. A row with neither field is
still the raw-id grant placeholder the filter was written to exclude.

## Unchanged on purpose

`cms_delete_agent_package` (0046) keeps calling authz with seven arguments
and therefore stays owner-or-admin.
