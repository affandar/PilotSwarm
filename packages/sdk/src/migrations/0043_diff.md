# 0043 — `agent_package_namespaces`

Package identity changes from a globally-unique `name` to the triple
**`(scope, owner, name)`**. Every user gets their own namespace; `shared` is
the deployment-wide one.

## Why

The first person to publish `triager` owned that word for the entire
deployment. Two users could not both have an agent by the same obvious name,
and nobody could take a personal copy of a shared package to modify.

## Schema

```sql
-- Drop the global UNIQUE(name) from the 0038 CREATE TABLE.
-- Looked up by DEFINITION, not by guessing the generated constraint name:
-- a schema restored from a dump may not have named it identically.
ALTER TABLE agent_packages DROP CONSTRAINT <resolved>;

CREATE UNIQUE INDEX agent_packages_shared_name_uniq
    ON agent_packages (name) WHERE scope = 'shared';

CREATE UNIQUE INDEX agent_packages_user_name_uniq
    ON agent_packages (owner_provider, owner_subject, name) WHERE scope = 'user';
```

Shared stays globally unique — it is the deployment's own namespace. Existing
rows were globally unique, so neither index can conflict on the way in and
there is nothing to reconcile.

## The resolver

`cms_resolve_agent_package_id(name, viewer_p, viewer_s, sel_scope, sel_owner_p, sel_owner_s, require_enabled) → package_id`

One place decides which copy a name refers to, so reads, writes and the
worker's agent lookup can never disagree.

| `sel_scope` | Means |
| --- | --- |
| `NULL` | Resolve: the viewer's own copy, else shared |
| `'shared'` | The deployment copy, explicitly (`__shared:` compiles to this) |
| `'user'` | A named owner's copy; no owner named ⇒ the viewer's own |

`require_enabled` exists because **shadowing is enable-sensitive**: a disabled
personal copy must fall through to shared (the recovery path), while a
mutation has to find the disabled row in order to re-enable it.

## Changed procedures

All mutation procs, plus `cms_get_agent_package`, gained three selector
arguments. Adding parameters creates an **overload** rather than replacing the
function, so each old signature is `DROP FUNCTION`-ed first — otherwise a
caller that missed the update keeps silently hitting the name-only version.

| Proc | Change |
| --- | --- |
| `cms_agent_package_authz` | +3 selector args; **admin fallback** |
| `cms_set_agent_package_scope` | +3; promotion/demotion conflict checks |
| `cms_set_agent_package_enabled` | +3 |
| `cms_pin_agent_package_version` | +3 |
| `cms_delete_agent_package` | +3 |
| `cms_publish_agent_package` | locks `(name, scope, owner)`; reserved-name gate |
| `cms_list_agent_packages` | +`shadowed` column |
| `cms_get_agent_package` | +3; two-pass resolve; admin fallback |
| `cms_get_agent_packages_install_manifest` | +`package_id` |

### Three decisions worth the ink

**The admin fallback is load-bearing, not a convenience.** Ordinary resolution
walks "my copy, then shared", which is correct for a user. But it would strand
two real classes of row with no owner triple to select them by: **NULL-owner
packages** (predating owner stamping, or minted by an admin in a no-auth
deployment) and **another user's private package**, which an admin must be
able to disable during an incident. Without the fallback both become invisible
*and undeletable* — a migration that quietly orphans existing data. Ambiguity
is refused rather than guessed: several copies sharing a name means the admin
must name one.

**`cms_get_agent_package` resolves twice.** Live rule first (enabled only),
then the disabled row. A read should answer "which copy do I actually get",
and shadowing depends on enablement — but a package whose only copy is
disabled must still be inspectable, or disabling your one copy would make it
invisible as well as inert with no way back through this API.

**`AGENT_PACKAGE_SCOPE_MISMATCH` is gone by design.** Publishing `user` when a
`shared` package holds the name is no longer a conflict — it is exactly how a
user takes a personal copy, which is the headline of this migration.

## The reserved prefix

`cms_publish_agent_package` refuses any name matching `__%` with
`AGENT_PACKAGE_RESERVED_NAME`.

Enforced in **SQL** rather than TypeScript because this is the one gate every
publish path funnels through — CLI push, portal upload, and the manager's own
import are three separate callers, and a TS-only check is one forgotten caller
away from letting somebody mint a package that captures every reference
meaning "the deployment's copy".

Verified: `__shared`, `__sneaky`, `__SHARED` refused; `_ok`, `normal` allowed.

## Install manifest gains `package_id`

Workers install every enabled package to disk, and two packages can now share
a `name`. The installer keys cache directories off this stable id
(`name@semver.sha.u<pkgid>` for user scope) — without it, two owners with
**byte-identical** content collapsed into one directory and the worker's
dir→owner map lost the provenance that keeps a user-scope agent private.
Shared packages keep the historical bare key so existing fleet caches stay
warm.

## Callers

- `PgSessionCatalog` — `AgentPackageSelector`, `selectorArgs()`,
  `resolveAgentPackageId()`, `shadowed` on summaries, `packageId` on install
  entries
- `agent-package-installer.ts` — owner-discriminated cache keys, name-keyed GC
- `session-proxy.ts` — `resolveAgentConfig` shadowing + `__shared:` handling

## Compatibility

Every existing row is globally unique, so both partial indexes are satisfiable
without a data fix. Pre-existing NULL-owner and foreign-owner packages stay
reachable through the admin fallback. A worker running against a schema
without 0043 fails its package queries and degrades — it does not corrupt.
