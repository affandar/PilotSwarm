# Diff for migration 0040

Migration file: `cms-migrations.ts` — `migration_0040_worker_registry`

Worker registry (docs/proposals/worker-registry.md rev 4): substrate-neutral,
uniformly ephemeral workers + the scoped desired-state channel. All-new
tables plus three SHIMS whose signatures are unchanged — the seamless-upgrade
mechanism for mixed fleets.

## Table Changes

### `workers` — new table

```sql
CREATE TABLE IF NOT EXISTS SCHEMA.workers (
    worker_node_id TEXT PRIMARY KEY,
    pool           TEXT NOT NULL DEFAULT 'default',
    phase          TEXT NOT NULL DEFAULT 'starting' CHECK (phase IN ('starting', 'ready', 'draining')),
    owner_provider TEXT,
    owner_subject  TEXT,
    registered_at  TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at     TIMESTAMPTZ NOT NULL DEFAULT now(),
    info           JSONB NOT NULL DEFAULT '{}'::jsonb,
    health         JSONB NOT NULL DEFAULT '{}'::jsonb,
    state          JSONB NOT NULL DEFAULT '{}'::jsonb
);
```

Presence, not enrollment: liveness is `updated_at` recency; rows silent > 1h
are pruned by the heartbeat, uniformly for every substrate.

### `fleet_directives` — new table

```sql
CREATE TABLE IF NOT EXISTS SCHEMA.fleet_directives (
    domain         TEXT NOT NULL,
    pool           TEXT NOT NULL DEFAULT '*',
    worker_node_id TEXT NOT NULL DEFAULT '*',
    epoch          BIGINT NOT NULL DEFAULT 1,
    actuation      TEXT NOT NULL DEFAULT 'worker' CHECK (actuation IN ('worker', 'external')),
    desired        JSONB NOT NULL DEFAULT '{}'::jsonb,
    updated_at     TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_by     TEXT,
    PRIMARY KEY (domain, pool, worker_node_id)
);
```

Seeded idempotently: `('agent-packages','*','*')` takes its epoch from
`agent_registry_state` so old and new workers observe ONE continuous
monotonic counter across the upgrade (fallback seed of 1 when the legacy
row is absent).

## New Indexes

```sql
CREATE INDEX IF NOT EXISTS workers_pool_idx ON SCHEMA.workers (pool);
```

## Function Changes

### New

```diff
+ cms_worker_heartbeat(p_worker_node_id, p_pool, p_phase, p_owner_provider,
+     p_owner_subject, p_info, p_health, p_state)
+     RETURNS TABLE(domain, epoch, actuation, desired)
+ cms_list_workers() RETURNS TABLE(...)
+ cms_fleet_directive_bump(p_domain, p_pool, p_worker_node_id, p_desired,
+     p_actuation, p_updated_by) RETURNS BIGINT
+ cms_get_fleet_directives() RETURNS TABLE(...)
```

`cms_worker_heartbeat` is the one round-trip: upsert (info/owner insert-only;
pool/phase/health/state/updated_at every beat — pool follows declared config
so re-targeting is the next beat), uniform 1h prune, then the effective
directive set — per domain the shallow-merge union (`fleet || pool || worker`
via `||`, worker > pool > fleet on conflicting keys) with epoch = SUM of the
contributing rows' epochs (monotonic under any single-row bump; max could
miss coincidentally-equal bumps).

`cms_fleet_directive_bump` enforces the canonical worker-row form
(worker-scoped rows use pool `'*'` — `FLEET_DIRECTIVE_BAD_SCOPE`) and
domain-uniform actuation (`FLEET_DIRECTIVE_ACTUATION_MISMATCH`); a NULL
`desired` is a doorbell bump keeping the existing payload.

### Shims — body modified, signatures unchanged (the mixed-fleet contract)

#### `cms_agent_registry_bump` — (baseline: 0038)

```diff
-    UPDATE SCHEMA.agent_registry_state
-       SET epoch = epoch + 1, updated_at = now()
-     WHERE id = 1
-    RETURNING epoch;
+    SELECT SCHEMA.cms_fleet_directive_bump('agent-packages', '*', '*', NULL, 'worker', 'agent-packages');
```

#### `cms_agent_registry_epoch` — (baseline: 0038)

```diff
-    SELECT epoch FROM SCHEMA.agent_registry_state WHERE id = 1;
+    SELECT COALESCE((SELECT d.epoch FROM SCHEMA.fleet_directives d
+                      WHERE d.domain = 'agent-packages' AND d.pool = '*' AND d.worker_node_id = '*'), 0);
```

Every 0038 agent-package mutation proc calls `cms_agent_registry_bump()` and
keeps working untouched; old workers polling `cms_agent_registry_epoch()`
keep seeing bumps. `agent_registry_state` stops being written but remains
until 0041.

#### `cms_list_agent_worker_state` — (baseline: 0038)

```diff
-    SELECT worker_node_id, epoch, installed, updated_at
-      FROM SCHEMA.agent_worker_state
-     ORDER BY worker_node_id;
+    SELECT DISTINCT ON (u.worker_node_id) u.worker_node_id, u.epoch, u.installed, u.updated_at
+      FROM ( SELECT ... FROM SCHEMA.workers w            -- state->'agent-packages' projection
+             UNION ALL
+             SELECT ... FROM SCHEMA.agent_worker_state a -- legacy rows (old workers)
+           ) u
+     ORDER BY u.worker_node_id, u.updated_at DESC;
```

Mixed-fleet display: newest row per worker wins, so during a rolling upgrade
old-path and new-path workers surface together in fleet adoption with zero
read-side changes. `cms_upsert_agent_worker_state` (0039 body) is untouched —
old workers keep writing it until the fleet is upgraded; 0041 drops both
legacy tables and the upsert.
