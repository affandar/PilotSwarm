## Table Changes

### `sessions`

```diff
+ context_tier            TEXT
+ model_resolution_source TEXT
```

The complete resolved tuple and its source are persisted with the session.

### `provider_bootstrap_receipts` — new table

One durable receipt per statically bootstrapped provider. Receipts are not
foreign-keyed to live provider rows, so deleting a seeded provider prevents it
from reappearing on restart.

### `system_agent_restart_rollouts` — new table

Stores one durable restart operation/claim per deterministic system agent.
Per-agent advisory transaction locks serialize the first claim; fresh
in-progress claims report busy, failed or stale claims are retryable, and
completed operations are idempotent. A partially failed system-default rollout
therefore resumes only unfinished agents without concurrent teardown.

## New Functions

### `cms_provider_assert_session_model`

Validates and key-locks the exact `provider:model` in the same transaction as
session creation. Ordinary sessions may use shared providers or their owner's
personal providers. System sessions may use shared providers or personal
providers explicitly enabled for system use.

### `cms_provider_rollback_legacy_session_models`

Admin-only rollback of active model labels recorded by migration 0058.

### `cms_provider_clear_routing_dependencies`

Explicitly clears ordinary/system defaults and per-agent overrides that refer
to a provider. Shared-provider cleanup requires admin; a personal provider
remains owner-managed. This is the deliberate prerequisite for dependency-safe
provider deletion.

### `cms_provider_claim_system_restart` / `cms_provider_finish_system_restart`

Per-agent advisory locks and durable rollout rows serialize system restarts.
Fresh claims report busy, failed/stale claims are retryable, and completed
operation IDs are idempotent.

## Replaced Functions

### `cms_provider_check_turn`

- Uses the system provider namespace for system sessions.
- Resolves legacy null system models through per-agent override, system default,
  then compatibility cluster default.
- Keeps ordinary user -> cluster precedence unchanged.

### `cms_provider_bootstrap`

- Replaces the one global all-or-nothing claim with per-provider receipts.
- A credential-poor process can seed what it has without blocking a later worker
  from adding missing providers.
- Any malformed entry fails the whole call and rolls back provider rows and
  receipts; partial half-seeds are not committed.
- The legacy static default is applied once, independently, only after its
  provider exists.
