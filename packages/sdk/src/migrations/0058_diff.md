# Diff for migration 0058

Migration file: `cms-migrations.ts` — `migration_0058_legacy_github_provider_migration`

## Table Changes

### `provider_legacy_key_migrations` — new table

```sql
CREATE TABLE provider_legacy_key_migrations (
    source_kind      TEXT NOT NULL CHECK (source_kind IN ('user','system')),
    source_user_id   BIGINT NOT NULL REFERENCES users(user_id) ON DELETE CASCADE,
    provider_name    TEXT UNIQUE REFERENCES provider_instances(name) ON DELETE SET NULL,
    migrated_at      TIMESTAMPTZ NOT NULL DEFAULT now(),
    PRIMARY KEY (source_kind, source_user_id)
);
```

This records only migration provenance. It contains no credential value or hash.
The receipt survives deliberate provider deletion so migration replay does not
recreate a provider the owner removed.

### `provider_legacy_session_models` — new rollback table

Stores original and migrated model labels for active sessions rewritten by the
migration. Completed/deleted historical sessions are not rewritten.

## Data Migration

For each non-System user with a populated legacy `github_copilot_key`:

- Create a personal `github-copilot` provider named `ghcp-u<user_id>`.
- Copy the credential into `provider_instances.secret_ref` entirely inside the
  database transaction.
- Record the user/provider mapping.
- Rewrite active non-system `github-copilot:<model>` session rows owned by that
  user to `ghcp-u<user_id>:<model>`.
- Retain the legacy key for dual-read rollback.

The synthetic System user's key is deliberately not migrated automatically.

## New Functions

### `cms_provider_adopt_system_github_key`

Admin-only explicit adoption of the synthetic System key into a personal
provider owned by the calling admin. The provider is system-enabled at creation.
The key never leaves PostgreSQL, and the legacy System key remains during the
rollback window. One durable receipt prevents a second admin or second provider
name from adopting the same key.

### `cms_provider_legacy_key_migration_status`

Returns aggregate counts and booleans only:

```text
regular_keys
migrated_regular_keys
system_key_present
system_key_adopted
```

It never returns credential material.
