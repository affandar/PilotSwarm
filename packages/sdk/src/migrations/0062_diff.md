# Diff for migration 0062

Migration file: `cms-migrations.ts` — `migration_0062_provider_ledger_base`

## Table Changes

### `sessions`

```diff
+ provider_ledger_base INTEGER NOT NULL DEFAULT 0
```

The lifetime offset for provider-ledger settlement keys. The ledger PK
(session_id, turn_index) is the exactly-once settlement claim; a restarted
system session RETAINS its session id while its fresh orchestration counts
turns from zero, so new-lifetime indexes collided with old rows and
`ON CONFLICT DO NOTHING` silently dropped the spend.

The orchestration input cannot carry the correction — `input.iteration` is
the resume/bootstrap discriminator, and seeding it sends a fresh lifetime
into a resume fail-loop (both failure modes live-verified 2026-08-24).

## Function Changes

### `cms_provider_bump_ledger_base` — new

Sets the session's base to `cms_provider_next_turn_index(session)`.
Called by the system-restart path (and worker recovery starts) before the
fresh orchestration begins. Idempotent when no new spend has landed.

### `cms_provider_settle_turn` — body modified (baseline: 0053)

The inserted ledger `turn_index` becomes `p_turn_index + provider_ledger_base`.
Everything else (meter upserts, key-share lock, charge-class rules) is
unchanged.
