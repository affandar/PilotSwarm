PilotSwarm · theme proposal · 3 themes × 3 surfaces

Three machines that sounded like they looked

WinAMP, DOOM and Quake shipped within four years of each other and share almost no visual DNA. That is what makes them a good set: pick any one and you have picked a mood, not a palette shuffle.

Each carries its own mark and header architecture, and each is shown on all three surfaces the portal actually ships: desktop, TUI and mobile. The TUI is the honest test — it strips gradients, bevels and shadows, leaving only the palette. A theme that dies there was chrome, not a theme.

WinAMP

2.x · 1997

Desktop is where it wins: the identity block becomes the now-playing display — context figure as the LED readout, user as the scrolling title, fleet counts where the bitrate goes.

TUI is where it hurts. Strip the bevels and the black glass and what remains is green text on black — very close to the existing Terminal Green theme, distinguished only by the amber and the ramp. This is the strongest theme on the surface with the most pixels and the weakest on the one with none.

Mobile holds: the display collapses to one glass strip with a smaller readout, which is exactly what Winamp's own shade mode did.

DOOM

id software · 1993

Warm brown metal and bone-coloured type. DOOM's status bar is the most recognisable strip of UI id ever drew — hammered brown, big red numerals, the marine's face dead centre.

Across the three surfaces

Desktop is the STBAR outright: numeric cells split by hammered seams, face recessed dead centre, keycards stacked right as live status lamps. Counts that hide in a corner today become big red numerals.

TUI survives better than expected. Bone-on-brown needs no gradient, and the keycard triad still reads as three coloured marks in a column. What is lost is the face and the metal — so the TUI is DOOM's palette without DOOM's furniture.

Mobile is where it strains. Five numeric cells do not fit 340px, so the bar sheds the identity to a second strip and keeps face, two counts and the keys. It works, but it is the only theme here that needs a different header layout on a phone rather than a smaller one.

Quake

id software · 1996

The murky one. Quake's palette is famously desaturated — wet stone, rust, and a single amber light source. The design idea is restraint: one colour, held back.

Desktop is a stone slab lit from one corner — the only gradient in the theme, doing a bevel's job without one. Counts sit in HUD amber with a faint bloom, the same light as the mark's core.

TUI is where it quietly wins. Nothing here depended on a gradient, so almost nothing is lost: amber on stone, parchment text, and the single quad-blue dot still pulling the eye to the running session. This is the only one of the three that looks like the same theme on all three surfaces.

Mobile is a straight shrink — logo, name, one amber figure. No layout change needed, because there was never more than one idea in the header.

What the three surfaces settled

Rendering the TUI changed the ranking twice. On desktop alone WinAMP is the most impressive of the three; across all three surfaces it is the least consistent, because everything that makes it WinAMP is chrome the terminal cannot draw.

ThemeDesktopTUIMobileBuild
Quake Strong — one lit slab Identical in feel Straight shrink ~½ day
WinAMP Best of the three Near Terminal Green Shade mode, holds ~2 days
DOOM Loudest, most fun Palette survives, furniture does not Needs its own layout ~2–3 days

Recommendation

Quake first, and now for a stronger reason than cost: it is the only one of the three that is recognisably the same theme in a terminal, on a phone and on a desktop. Its restraint is not timidity — it is what makes it portable across surfaces that have wildly different capabilities.

WinAMP second, with eyes open: it will be the one people screenshot, and the one that disappoints in the TUI. If that matters, its terminal variant should lean much harder on the amber and the status ramp than the desktop one does, so it is not mistaken for Terminal Green.

DOOM last. Most fun, least restful, and the only theme needing a genuinely different header layout on mobile rather than a smaller one — which is where the extra day goes.

What building one costs

Themes are data: one file under packages/app/ui/core/src/themes/ exporting createTheme({ id, label, description, page, terminal }), plus one import in themes/index.js. ms-dos.js and win95.js are the models. The terminal block is what drives the TUI column above, so it is not an afterthought — it is half the theme.

Learned the hard way, today

Both existing retro themes carry .is-selected * { background-color: transparent } to stop child backgrounds punching holes in the selection bar — and it silently erased the two elements that are their background: the status dot and the owner disc. Measured in a browser, both were fully transparent on the selected row in MS-DOS and Win95 alike. Any theme that restyles selection must explicitly restate those two marks, or they vanish and nothing complains.

One live constraint: the suite enforces a muted-text contrast floor (theme-muted-contrast.test.js). Authentic CGA dark grey already failed it once and MS-DOS carries a documented deviation. Expect the same for DOOM's darker browns and Quake's stone greys — the honest move is to deviate and say so in a comment, as ms-dos.js does.
